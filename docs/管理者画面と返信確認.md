## 管理者の操作

管理者としてログインすると `/check_annotator/admin` へ移動する。ヘッダーにも「管理者画面」を表示する。

- 有効な作業者ごとに、担当グループ数・担当タスク数・完了数・状態ごとの件数・管理者未返信コメント数を確認できる。未割り当て分は専用の件数で表示する。削除済みレコードは集計対象外。
- 「担当グループ」で既存のグループ・タスク画面を開ける。
- 「進捗を更新」で集計を再取得する。
- コメントは作業者で絞り込みできる。最初は「管理者が未返信のコメントのみ」が選択される。チェックを外すと返信済みの作業者コメントも表示する。
- 「このコメントに返信」で、選択したコメントを返信先にした入力欄を開く。送信前の確認ダイアログを経由して保存する。
- 返信は既存の `parent_id` に紐づける。返信一覧から開いたフォームでは返信先の取り消しや別コメントへの切り替えを表示しない。返信失敗時は入力内容を保持する。

「未返信」は、有効な管理者による有効な直接返信がないコメントを意味する。既読・未読の状態ではない。作業者が管理者の返信へさらに返答すると、その返答は新しい返信待ちとして管理者一覧に表示される。

## 担当者の設定

管理者画面の「タスクの割り当て設定」で「範囲を追加」を押し、「開始画像ID」「終了画像ID」「担当者」を指定する。例えば50〜1249など、1,000件の区切りによらない範囲を複数設定できる。同じ担当者への複数範囲の設定も可能。「選択内容を確認して保存」で一覧を確認し、「この内容で割り当てを更新」で保存する。入力だけでは反映しない。

保存は割り当て全体の置き換え。指定範囲に合うグループを作成・再利用し、以前の1,000件区切りなど使わなくなったグループは非表示にする。指定外の既存タスクは「未割り当て」にまとめる。範囲の重複、開始・終了の逆転、存在しない画像ID、同じ画像IDの重複タスクを拒否する。画像やタスクの新規投入は行わない。

タスクID・画像ID・状態・タスクの日時・コメントは保持し、タスクの所属グループだけを移す。過去のグループへのURLは無効になる場合があるため、作業者は担当グループ一覧を再読み込みする。古い区切りは保存時に整理するので、サーバーへのコード反映だけでは割り当てを変更しない。

「すべて未割り当てとして選択」で一覧を空にすると一括解除の準備ができる。こちらも確認・保存が必要。各行の「削除」は範囲の指定を外す操作で、画像・タスクは削除しない。他の管理者が先に割り当てを変更した場合や対象画像が変わった場合は全件の保存を取り消し、エラーを表示する。「最新に更新」で再取得して選び直す。

設定は管理者のみ操作できる。一般作業者・削除済みユーザー・管理者アカウントへの不正な割り当てをAPI側でも検証する。初期投入用の `scripts/assign_tasks.py` ではなく、この画面で既存グループを再割り当てする。

一括解除スクリプト `scripts/unassign_tasks.py` は既定で確認のみ。実行対象・想定件数を検証し、バックアップを保存してから担当者だけを解除する。タスク・コメントの全行の内容が変わらないことも検証する。

## 作業者の操作

作業者はヘッダーの「返信一覧」から `/check_annotator/replies` を開く。

- 現在担当しているタスクへの管理者の返信を、新しい順に表示する。
- 管理者名・返信先のコメント内容・返信本文・画像ID・担当グループを確認できる。
- 管理者の返信へ、さらに回答できる。
- 「担当タスクを開く」で元のタスク画面に戻れる。従来のコメント一覧でも同じ返信を閲覧できる。
- 自分に割り当てられていないタスクの返信は取得できない。担当が変更された場合は、現在の担当者だけがそのタスクの返信一覧を取得できる。

コメント一覧・返信一覧は20件ごとのページ分割。返信欄を開いていない場合に、画面への復帰時と30秒ごとに更新する。入力中に内容を消さないよう、返信欄を開いている間は自動更新・フィルター・ページ切り替えを停止する。

## APIと権限

| API | 用途 | 権限 |
| --- | --- | --- |
| `GET /api/admin/overview` | 作業者別の進捗・未返信件数 | 管理者のみ |
| `GET /api/admin/assignments` | 未割り当てを含むグループ一覧 | 管理者のみ |
| `POST /api/admin/assignments` | 担当者の一括設定・解除 | 管理者のみ・競合時は全件取消 |
| `GET /api/admin/assignment-ranges` | 現在の範囲・対象件数・変更検出用の情報 | 管理者のみ |
| `POST /api/admin/assignment-ranges` | 範囲と担当者による全体の再編成 | 管理者のみ・検証失敗や競合時は全件取消 |
| `GET /api/admin/comments` | 作業者コメント一覧 | 管理者のみ |
| `GET /api/users/me/replies` | 現在担当するタスクの管理者返信 | ログインユーザー自身の担当分のみ |
| `POST /api/tasks/{task_id}/comments` | コメントへの返信 | 既存のタスク権限と同一タスクの返信先を検証 |

画面の表示制御に加えて、APIでも権限を検証する。既存のテーブルとコメントの親子関係を利用し、DBスキーマ変更は不要。ユーザー作成・権限変更・メール送信は行わない。

## 検証

API全体は隔離されたSQLiteでテストする。新しい管理者API、一般作業者の403、他作業者の返信分離、返信先のタスク一致、削除済みデータ、ページ分割、担当変更を確認する。

フロントは管理者ログイン時の遷移、作業者の管理画面拒否、選択コメントへの返信、失敗時の入力保持、作業者の返信表示、および既存のカテゴリ・タスク・コメント画面をテストする。最後に確認専用の仮データ上で、質問→管理者返信→作業者の返信確認をブラウザで検証する。
