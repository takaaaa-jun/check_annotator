# Viteの導入

## 外部MySQLへの接続

本アプリケーションはDocker Compose内にMySQLを作成せず、サーバ上の外部MySQLへ接続する。

1. `.env.example` を `.env` にコピーする。
2. 次の値を接続先に合わせて変更する。

   ```env
   APP_DATA_MODE=database
   DATABASE_URL=
   DB_HOST=192.0.2.10
   DB_PORT=3306
   DB_NAME=check_annotator
   DB_USER=check_annotator_app
   DB_PASSWORD=replace-with-database-password
   DB_SSL_CA=
   DB_CONNECT_TIMEOUT=5
   DB_POOL_RECYCLE=1800
   ```

3. バックエンドを再作成する。

   ```powershell
   docker compose `
     --env-file .env `
     -f docker-compose.yaml `
     -f docker-compose.dev.yaml `
     up -d --build --force-recreate backend
   ```

4. DBヘルスチェックを確認する。

   ```powershell
   Invoke-RestMethod http://localhost:8000/health/database
   ```

   接続成功時は次を返す。

   ```json
   {
     "status": "ok",
     "database": "connected"
   }
   ```

   MySQLへ接続できない場合はHTTP 503と `database: unavailable` を返す。レスポンスには接続先や認証情報を含めない。

### 設定上の注意

- `DB_HOST` にはサーバのIPアドレスまたは名前解決可能なホスト名を指定する。
- `DATABASE_URL` を設定すると、個別の `DB_*` より優先される。
- `.env` はGitへコミットしない。
- MySQL側ではアプリケーションサーバからの接続だけを許可し、アプリ用ユーザーには必要最小限の権限を付与する。
- ファイアウォールでMySQLのポートをインターネット全体へ公開しない。
- TLSが必要な場合は、バックエンドコンテナから読み取れるCA証明書のパスを `DB_SSL_CA` に指定する。ホスト上のファイルは、同じパスまたはコンテナ内の指定先へ読み取り専用でマウントする。
- 接続確認に失敗した場合は、IPアドレス、ポート、DB名、MySQLユーザーの接続元制限、ファイアウォール、CA証明書を順に確認する。パスワードや完全な接続URLをログへ貼り付けない。

### ヘルスチェックの使い分け

| URL | 用途 | DB停止時 |
| --- | --- | --- |
| `/health` | FastAPIプロセスの生存確認 | 200 |
| `/health/database` | アプリからDBまでの稼働確認 | 503 |

開発用SQLiteモックモードでも `/health/database` を使用できる。Docker ComposeはこのDBヘルスチェックを利用する。

- ローカルで一度だけ実行

```bash
npm create vite@latest . -- --template react-ts
```
